# Frontend parity and cutover

This page is the shipped record of the native-shell parity campaign: how the
React/Tauri frontend was replaced by `crates/stratum-ui`, what was verified
before the cutover, and what the gates are now.

The working plan is `.hermes/plans/2026-11-08_101000-gpui-frontend-implementation.md`
(gitignored); the machine-readable reports live in `.hermes/parity/` and are
regenerated by the scripts named below.

## 2. How parity was verified

### 2.1 Golden screenshots

`scripts/verify-gpui-goldens.sh` captures every shipped state on a private Xvfb
screen — desktop at 1440×900 (2 shell states + 47 panel states), mobile at
1080×2400 (15 states) — and diffs each capture against the committed golden in
`goldens/gpui/` using normalized RMSE. The gate fails above the tolerance
(0.02 locally, 0.05 in CI where font rasterization differs). `--update`
regenerates the set; the resulting image diff must be reviewed before commit.

64 surfaces, 64 goldens. The mobile capture script additionally fails unless
every PNG is exactly 1080×2400.

### 2.2 Differential command tests

The web frontend was a thin adapter over `stratum_app::StratumService`, so
parity is structural. `crates/stratum-ui/tests/command_parity.rs`:

1. parses the shipped inventory in `docs/development/service-layer.md`
   (128 rows) and asserts every command resolves to a live public
   `stratum-app` method — so "no unimplemented feature" stays checkable after
   the web shell is gone;
2. drives the same fixture vault through the service and through the native
   provider seam and asserts the two views agree row for row.

### 2.3 Performance budgets

`scripts/verify-gpui-perf.sh` measures and gates:

| Budget | Measurement | Result |
|---|---|---|
| Editor: 10 000-block virtualized scroll ≥ 55 fps | `stratum-editor-perf`, render p95 ≤ 18.18 ms | render p95 **2.47 ms** (600 frames, 10 000 blocks, 2 rows rendered) |
| Graph: deterministic layout/render fps | `graph_golden --assert-fps` | passes: 1299 fps at 200 nodes … 175 fps at 20 000 nodes |
| Canvas: 5k-element build/pan frame budget | `cargo test -p stratum-canvas --test perf` | 5/5 pass |
| Cold start ≤ 500 ms | release binary, first mapped window | **324 ms** |
| Idle memory ≤ 80 MB | release binary, `RssAnon` after an 8 s settle | **49.1 MB** (total VmRSS 230.6 MB, of which 158.7 MB is file-backed graphics/ font mappings every GPU process shares) |

The startup probe only gates the release profile; a debug run reports its
numbers with a note (a debug shell carries debug info and unoptimized
allocations, so its RSS is not a shipping signal). The memory budget is read
from `RssAnon` because `VmRSS` is dominated by the Vulkan ICD, Mesa/llvmpipe and
font-cache mappings that the driver — not the shell — owns; both figures are
recorded in `.hermes/parity/perf-report.json`.

### 2.4 Accessibility

`scripts/verify-gpui-a11y.sh` runs the AccessKit probe
(`crates/stratum-ui/src/bin/a11y_probe.rs`) inside a private D-Bus session and
audits the tree: every interactive role (button, link, checkbox, textbox, tab,
combobox, menuitem) must expose a non-empty accessible name, and no name may be
a raw catalog key. When no assistive technology is connected gpui does not build
the tree; the probe reports `inactive` and the gate says so instead of failing.

### 2.5 Raw-key scan

`crates/stratum-i18n/tests/raw_keys.rs` walks the shell sources, extracts every
literal key passed to `t_global`/`tr_global` and fails when a key is absent from
the English catalog (and therefore from all eight, which the parity gate keeps in
lock-step). Panel contract tests additionally verify each `*_I18N_KEYS` list
against every catalog.

## 3. The cutover

Deleted: `src/` (React + TypeScript), `src-tauri/` (Tauri shell, IPC adapters,
capabilities), `e2e/` (Playwright harness), `verification/cdp_probe.mjs`,
`package.json` + lockfile, `tsconfig*.json`, `vite.config.ts`, `vitest.config.ts`,
`eslint.config.js`, `knip.json`.

Consequences:

- `Cargo.toml` no longer lists `src-tauri`; `crates/pkm-tests` drives
  `stratum_app` directly instead of the `app_lib` adapter crate.
- CI is one workflow (`.github/workflows/ci.yml`): repo hygiene, workspace
  fmt/clippy/test, the Windows/macOS shell gate, the parity harness, the Android
  build + emulator smoke, MCP coverage and `cargo audit`. `.github/workflows/gpui-ci.yml`
  was folded into it. Release packaging stays in `gpui-release.yml`.
- The npm/npm-audit/dependabot-npm lanes are gone; the Mermaid bundle is vendored
  in `crates/stratum-app/assets/` (MIT, licence file alongside), so the workspace
  builds without Node.
- `stratum-i18n` owns the eight catalogs; the JSON files under `src/i18n/` were
  deleted with the web app.
- The Nix dev shell dropped `nodejs`/`cargo-tauri`/WebKitGTK and now provides the
  native windowing, Vulkan and ALSA stack; `packages.default` builds
  `crates/stratum-ui`.
- `docs/development/frontend-guide.md` was deleted (it documented React
  components/hooks); `docs/development/gpui-ui.md` is the shell reference.
- The frozen web build remains available as the `v1.0.0` tag for historical
  comparison; no branch is maintained for it.

## 4. Reproducing the evidence

```bash
nix develop ./nix

# workspace gates
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
RUSTFLAGS="-D warnings" cargo test --workspace

# parity harness
./scripts/verify-gpui-goldens.sh   # golden screenshots (64 surfaces)
./scripts/verify-gpui-perf.sh      # perf budgets + startup/RSS
./scripts/verify-gpui-a11y.sh      # accessibility tree audit
```

Reports are written to `.hermes/parity/` (goldens, perf) and `.hermes/a11y/`;
they are gitignored by design — the durable record is this page plus the
committed goldens.
