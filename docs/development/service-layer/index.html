    Headless service layer (stratum-app)¶

    crates/stratum-app owns the business logic behind every Tauri IPC command. It is a plain Rust library: it has no dependency on tauri or any tauri-plugin-* crate, so the same logic runs in the desktop shell, on mobile hosts, in integration tests, and in the CLI-adjacent tooling without spinning up a Tauri runtime.

    The Tauri shell (src-tauri) is now a thin adapter layer:

    frontend invoke() ──► src-tauri/src/commands/*  (IPC adapter)
                             │  state: StratumService
                             ▼
                      crates/stratum-app/src/*   (business logic)
                             │
                             ▼
        pkm-core / pkm-block / pkm-index / pkm-sync / …

    The split is intentional: command names, argument names, DTO shapes, event names/payloads, error strings, and on-disk formats are unchanged. Moving the code did not change the public contract; it only changed where it lives.

    Entry point¶

    All commands are exposed as associated functions on stratum_app::StratumService, a cloneable handle around the shared vault state (crates/stratum-app/src/state.rs). The method name matches the IPC command name, and the argument list matches the IPC arguments minus state/app (host handles supplied by the adapter).

    use stratum_app::{EventSink, StratumService};

let service = StratumService::new(vault_path);
let info = service.get_vault_info().await?;

    Operations that used to call AppHandle::emit take an EventSink instead. Hosts implement that trait over their own event bus; tests can record emitted events; and NoopSink discards everything. Event names and payload shapes are identical to the pre-extraction Tauri events (for example reindex-progress, dictation:stage, dictation:done, mic-permission-request).

    Adapter rules¶

    Every adapter in src-tauri/src/commands/ must:

    1. Take tauri::State<'_, StratumService> (or tauri::AppHandle when platform APIs are needed) and forward the arguments verbatim.
    2. Call exactly one service method. Do not add business logic to the adapter.
    3. Forward events through an EventSink implementation backed by the AppHandle (src-tauri/src/commands/events.rs).
    4. Keep platform-only work (folder pickers, tray icons, window management, OS notifications, global shortcuts, Android SAF) in the adapter, calling the service only for the vault/data mutation.
    5. Return the service result unchanged — no error-string rewriting.

    src-tauri/src/lib.rs stays a small bootstrap file; the IPC registry lives in src-tauri/src/invoke.rs and the boot sequence in src-tauri/src/setup.rs.

    Testing¶

    Headless tests live in crates/stratum-app/tests/, one file per domain (vault_service.rs, page_service.rs, block_service.rs, …). They drive StratumService directly with a real temp vault and a RecordingSink that captures events — no Tauri runtime and no IPC serialization. This is the preferred place for new command coverage; the src-tauri integration tests remain as end-to-end checks of the IPC adapters.

    Tests that need an external service use wiremock (AI, STT, TTS, WebDAV). Tests that need a microphone or a Chromium binary skip cleanly when the resource is unavailable.

    Adding a command¶

    1. Implement the logic as a StratumService method in the matching crates/stratum-app/src/ module. Keep the IPC command name, argument names, DTOs, and error strings.
    2. Add a thin #[tauri::command] adapter in src-tauri/src/commands/, register it in src-tauri/src/invoke.rs, and add the typed wrapper in src/lib/commands.ts plus the DTO in src/lib/types.ts.
    3. Add a headless test in crates/stratum-app/tests/ that calls the service method directly.
    4. Update the table above and any user-facing guide that documents the feature.
