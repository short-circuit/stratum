    Headless Block-Editor Engine¶

    crates/stratum-editor (lib stratum_editor) is the headless editor core for the native GPUI shell. It is deliberately UI-free: no gpui, tauri or web dependencies. Every editing rule, inline-span parse, undo record, IME transition, menu catalog, marker/reminder model, WYSIWYM decoration and virtualization calculation lives here so the phase-B view can be a thin renderer over render::DecoratedRow values.

    The React + Tauri application in src/ and src-tauri/ was the behavioural and visual reference for this crate until the E12 cutover deleted it. The crate ported the pure helpers from src/components/OutlinerEditor, src/components/AISlashMenu.tsx, src/lib/wikiLinks.ts and src/lib/reminders/reminderUtils.ts; the shipped rules now live here and are pinned by tests/editor_contract.rs and the committed goldens.

    Crate Layout¶

    crates/stratum-editor/
├── src/
│   ├── lib.rs            # module map, re-exports, EDITOR_I18N_KEYS release gate
│   ├── document.rs       # EditorDocument, canonicalization, save bookkeeping
│   ├── dto.rs            # BlockDto/PageDoc, stratum_app-compatible seam
│   ├── inline.rs         # span parser + byte-exact serializer
│   ├── markers.rs        # marker detection, badge rows, reminder chips
│   ├── menus.rs          # slash catalog, marker menu, wiki autocomplete, link hits
│   ├── assets.rs         # attachment classification, row labels, thumbnail cache
│   ├── state/            # caret/selection, edits, moves, undo, clipboard, IME
│   ├── render.rs         # WYSIWYM decoration model (no UI types)
│   └── virtualize.rs     # deterministic heights and viewport windows
└── tests/                # round-trip, scripted editing and i18n contract suites

    Every module carries //! documentation, public items are documented, and the non-obvious algorithms (depth-preserving serialization, history coalescing, UTF-16 boundary rejection, paste normalization) have inline comments explaining the invariants.

    Byte-Stability Contract¶

    The editor writes the same plain Markdown block format as the shipped app. EditorDocument::body and canonicalize_body serialize the block tree with the shipped pkm_markdown::block_parser::serialize_blocks formatting rules (content, .marker, .priority, .heading-level, sorted properties, .id last) and preserve block depth: the serializer emits blocks in BlockTree::depth_first_order order with each block's real tree depth as indentation. The editor never re-implements serialization.

    Sibling order is deterministic: BlockTree keeps a first-insertion order and uses it as the tie-break when several siblings have no left_id (or when the left_id chain is broken). An explicit chain always wins, so canonical files serialize in their recorded order, while unordered input keeps the order the store or parser handed to the editor. Serialization never depends on HashMap iteration order.

    • Canonicalization is idempotent: canonicalize_body(canonicalize_body(x)) == canonicalize_body(x).
    • A canonical file round-trips byte-identically through canonicalize_body.
    • Parse → serialize is not byte-identical for arbitrary non-canonical input: ids are injected and properties are reordered. Those are deliberate normalizations, not data loss.
    • Saves re-assemble the original YAML frontmatter via assemble_blocks_markdown; the editor never rebuilds frontmatter from a title.

    tests/roundtrip.rs pins the canonical fixtures (nested children, code fences, Mermaid, math, wiki-links, tags, embeds, CJK) and the idempotency of the non-canonical corpus.

    Inline Spans¶

    inline::parse_inline recognizes emphasis, code, highlight, wiki-links and embeds, Markdown links, tags, math and block references. The parser is non-recursive: the first matching construct wins and its inner text is kept verbatim, so nested markers degrade to plain text. Escapes are preserved as text and unclosed markers degrade to text one scalar at a time. render_inline(parse_inline(s)) == s is guaranteed for every accepted input.

    Span records start_byte/end_byte so the view can map a caret or a ctrl-hover to a span without re-parsing.

    Editing, Undo and IME¶

    state::EditorState owns one document plus caret/selection, undo history, clipboard payload and IME composition.

    • Structural edits (insert_text, insert_newline, backspace, delete_forward, indent, outdent, move_up, move_down, merge_block, set_marker, set_priority, apply_span, toggle_collapsed) all go through pkm_block::ops. Caret byte offsets are clamped to UTF-8 char boundaries before split_block, which panics on a non-boundary.
    • Undo is expressed as concrete forward/inverse EditOp pairs, never document snapshots. History keeps at most 200 entries, coalesces contiguous text insertions in the same block at contiguous offsets within 750 ms, clears the redo stack on a new edit, and applies the inverse on undo. Split/merge ops carry the child list so undo restores deleted subtrees.
    • Clipboard: copy_selection/cut_selection build ClipboardPayload with plain text and BlockDtos. normalize_paste converts CRLF/CR to LF, strips NUL/control characters, expands tabs outside fenced code, strips trailing spaces, collapses 3+ blank lines, and caps input at 100 000 characters. paste_markdown splits paragraphs into blocks and maps leading list markers to indent depth.
    • IME: ime_replace stores the marked UTF-16 range and updates content without pushing history; ime_commit pushes exactly one history entry; ime_cancel restores the pre-composition content. utf16_to_byte rejects offsets that land inside a surrogate pair.

    Cross-block delete and multi-block paste are recorded as one reversible EditOp::SpliceBlocks entry: it carries the full removed/inserted block snapshots plus explicit parent/left (LinkChange) and content (ContentChange) deltas, so a single undo restores every removed block and re-linked sibling and redo re-applies the whole range operation. The wiki autocomplete popup lists only the rows it actually renders (wiki_row_count, capped at 8), so arrow-key selection and Enter can never reference an unrendered target; a no-match query renders the single "create page" row and closes the [[query link on Enter.

    WYSIWYM Model and Virtualization¶

    render::render_page classifies blocks (Paragraph, Heading, Quote, Code, Mermaid, Math, ListItem, Divider, Table) and produces DecoratedRows with depth, marker/priority badges, reminder chips, collapsed state and decorated spans.

    • RenderMode::StageA keeps every syntax delimiter visible (syntax = true).
    • RenderMode::FocusedLine hides delimiters only for the focused block; every other row stays Stage A.
    • A marker keyword at block start is never rendered as text: it is represented by the badge.

    virtualize::VirtualLayout provides deterministic height estimates, offsets, visible_window, scroll_top_for_block, block_at_offset and anchor_offset. Heights also reserve 18 px per explicit line break in code and multi-line prose, because each break renders as its own visual line; without that term a multi-line code block overlaps the following row. The 10k-row tests pin the window bound (viewport rows plus two overscan windows), monotonic offsets, the inverse scroll mapping and the line-break reservation.

    Math and Mermaid Caches¶

    math::MathCache, mermaid::MermaidCache and assets::AssetThumbnailCache are bounded LRU caches (with_capacity; defaults 64 math images, 32 SVG diagrams and 32 decoded thumbnails). Math renders through the pure-Rust RaTeX pipeline (ratex-parser → ratex-layout → ratex-render) and Mermaid through mermaid-rs-renderer; neither cache grows without bound. render_page_with_assets fills the math and mermaid fields of DecoratedRow; failures leave those fields None so the decorated text spans remain visible. The pure render_page path leaves both fields empty and is what the contract tests and the row builder use. DecoratedRow::thumbnail is always None from the renderer: the view decodes it lazily through ShellData::read_asset_thumbnail, exactly like math and Mermaid, so the headless crate stays I/O-free.

    Native Editor View (Phase B)¶

    The view lives in crates/stratum-ui/src/panels/editor/ and is split so every file stays under the repository limit:

    crates/stratum-ui/src/panels/editor/
├── mod.rs       # EditorView state, save scheduling, asset budget
├── view.rs      # Render impl: badge strip, virtual list, canvas input, overlays
├── rows.rs      # row/span/caret geometry and elements (+ rows/tests.rs)
├── asset_rows.rs # thumbnail / file-attachment row rendering
├── asset_state.rs # thumbnail budget, attachment list, drop-target resolution
├── asset_actions.rs # import/delete/attach flows (background executor)
├── attachments.rs # attachment panel (list, inline delete confirm, attach button)
├── metrics.rs   # per-frame render measurements for the 10k capture
├── input/       # input/mod.rs: EntityInputHandler, keys, mouse, overlay_ops, IME
├── overlay.rs   # slash, wiki, marker, link-preview and dead-link popups
├── drag.rs      # gutter drag state, drop-target resolution and the indicator bar
├── context_menu.rs # right-click block menu (read aloud, clipboard, marker, reminder)
└── save.rs      # SaveState/SaveStatus transitions

    EditorView owns the EditorState, the math/Mermaid/thumbnail caches, the attachment list, the VirtualLayout, the VirtualListScrollHandle, save status, overlay state, the focus handle and the ShellData provider. It delegates every editing rule to stratum_editor; the view never re-parses block text.

    Rendering and virtualization¶

    Rows are produced by build_rows_for_state, which calls stratum_editor::render_page and therefore never re-implements decoration. The view uses v_virtual_list(...).track_scroll(...) with the deterministic VirtualLayout heights and materialises only the visible window plus overscan. Math and Mermaid images are rendered lazily for the visible range with a budget of one new asset per frame, so a window full of diagrams cannot blow the frame work budget. Attachment thumbnails share that budget: the virtual-list closure calls ensure_thumbnails_for_range next to ensure_assets_for_range, so at most one decode is started per frame and the decode time is reported as part of asset_p95_ms. Image rows reserve ASSET_IMAGE_ROW_HEIGHT and file rows ASSET_FILE_ROW_HEIGHT in VirtualLayout::from_rows before a thumbnail exists, so scrolling stays correct while the preview is still missing. Row geometry (text left, depth indent, chevron, badge and reminder gutter) is deterministic and shared by the caret and mouse hit testing.

    EditorView::set_auto_height(true) switches the view from filling its parent to sizing itself to the full content height. The journal stack uses that mode so several day editors can live inside one scroll container; auto-height editors omit the page-level attachment panel, matching the shipped JournalPanel, which never renders AttachmentPanel.

    Input, IME and clipboard¶

    input/mod.rs implements EntityInputHandler and registers it from the editor canvas during paint (window.handle_input), which is the only valid time to install an input handler in gpui. It maps UTF-16 platform ranges onto the engine's UTF-8 byte offsets through utf16_to_byte/byte_to_utf16 and forwards marked ranges and commits to EditorState::ime_replace/ime_commit. Key handling covers caret movement and selection, undo/redo, clipboard, marker toggling and overlay navigation. Handled keys stop propagation; printable characters are left to the platform so they are inserted before overlay detection runs. Pointer handling — caret placement, Ctrl+hover previews, the right-click menu and gutter drags — lives in input/mouse.rs.

    Drag-and-drop reordering¶

    Blocks can be reordered by dragging. A press on a row's indent gutter (the empty space left of the row text) starts a drag instead of placing the caret, so text selection inside the row keeps working; a press that never travels places the caret at the start of that row. Rows show a grab cursor over the gutter. Once the pointer travels past drag::DRAG_THRESHOLD_PX (4 px) the view resolves a DropTarget from the hovered row and paints one 2 px indicator line in the theme's primary colour; Escape cancels the gesture.

    The hovered row is split into three zones: the top quarter inserts the dragged block above it, the bottom quarter below it (both as siblings at the hovered row's depth), and the middle drops onto it as its last child (indicator one indent level deeper). The destination group is resolved through BlockTree::children/roots, so the index always counts the siblings that remain after the dragged block is removed. Drops that would be a no-op, that target the dragged block itself, or that would place a block inside its own subtree are suppressed: no indicator is shown and releasing does nothing.

    The move goes through EditorState::move_block(block_id, MoveTarget) in crates/stratum-editor/src/state/moving.rs. It validates the destination parent, rejects cycles with PkmError::CycleDetected, clamps the index, applies pkm_block::ops::move_block inside EditorDocument::mutate, and records one reversible EditOp::MoveBlock entry, so a drop is undone by a single undo step exactly like move_up/move_down. A moved block's subtree moves with it.

    pkm_block::ops relinks left_id only inside the affected sibling group (group/successor_in_group): left_id == None is a head pointer local to a parent, so a tree-wide scan would let an unrelated parent's first child answer for another group's head and be relinked across parents. Sibling order stays deterministic and never depends on HashMap iteration order. create_block, delete_block and move_block reject a cross-parent after_id/new_left_id with PkmError::Validation instead of silently relinking the wrong group.

    Every geometry and target helper is a pure function over DecoratedRow, VirtualLayout and EditorState values, so the drag contract is unit-tested without a window (drag/tests.rs); only drop_indicator builds an element. handle_mouse_up applies a resolved drop through the shared finish_edit bookkeeping, and a no-op drop does not dirty the document.

    Overlays and navigation¶

    After a text insertion the view inspects the focused block for /, [[ and : tokens and opens the slash, wiki or marker overlay. The slash catalogue comes from stratum_editor::menus; wiki targets resolve against the provider's recent pages. Ctrl+hover opens a link preview through stratum_editor::menus::preview_for, which only previews wiki links (matching wikiLinks.ts, where tags, external URLs, block refs and asset embeds have no popup): a resolved target shows the shipped backlink_snippet_body.ctrl_click_to_navigate hint, while an unresolved one keeps editor.create_page because Ctrl+click offers creation. The preview is dismissed when Ctrl is released, not only on the next pointer move. Ctrl+click on a tag sets a pending navigation that the shell polls and turns into a route change. Ctrl+click on a wiki-link resolves it through stratum_editor::menus::resolve_wiki_target: an existing page navigates directly, while a missing target opens the dead-link popup. Enter or a click on that popup calls ShellData::create_page, then sets a pending navigation to the returned path; an "already exists" failure still navigates, mirroring DeadLinkCreatePopup.tsx. The shell refreshes its snapshot before resolving and opens a .md create-intent path directly.

    The slash popup draws exactly stratum_editor::menus::slash_row_count(items) rows (capped at SLASH_MAX_ROWS = 17) and the overlay selection length is the same count, so a selectable index is always a drawn row. The popup scrolls vertically within a 440 px maximum height and applies the same padding per row as the other menus. apply_slash clamps the selected index to the filtered catalogue, closes the overlay when the query matches nothing, and resets OverlayState::None after every applied action.

    AI slash actions¶

    The engine owns the AI request model and result application. menus/ai.rs exports AiCall, AiCallKind, AiCallScope, AiTransformAction and ai_call_for, which mirrors src/components/AISlashMenu.tsx: selection actions require a non-empty selection; page-scope prompts are plain text built by EditorDocument::plain_text (extractText parity — block content in document order, nested children joined with newlines, no frontmatter or property lines); interlink uses EditorDocument::plain_markdown_lossy (BlockNote blocksToMarkdownLossy parity — property-free - bullets and heading lines); research prefers the page text, then a captured selection, then the page path; and Mermaid prefers a selection, then the page text. ai_call_for returns None for block actions and for an empty resolved prompt, so the service is never called with an empty string.

    The view (panels/editor/ai.rs) executes the request off the UI thread: start_ai runs ShellData::ai_run on the background executor and finish_ai applies a non-empty result through EditorState::apply_ai_content, clears the status for empty results, and keeps the document unchanged on failure while surfacing the provider message. EditorState::apply_ai_content dispatches on the call scope: ReplacePage parses the markdown into a single undoable SpliceBlocks replacement, InsertAtCaret normalizes and inserts the text at the caret, and InsertBlockAfterCaret wraps the result in a Mermaid fence and adds it as a sibling block. The running/failed state takes precedence in the save chip, so an AI request is visible while it runs and its error is shown instead of a stale "saved" label.

    ShellData::ai_run is a trait method with a default echo implementation for providers without AI support. AppProvider maps it onto the service layer: transforms call ai_transform_block with the corresponding AiAction, research calls ai_research, interlink calls ai_interlink_notes and Mermaid calls generate_mermaid. Every ai_transform_block request carries the page path (the service uses it to pick journal vs. page context), exactly like AISlashMenu.tsx; research and Mermaid send only their prompt.

    Slash catalogue mapping¶

    Inserting code, Mermaid or math places the caret on the first line inside the opening fence, so the next keystrokes stay inside the block and keep it classified as code/Mermaid/math.

    Action id Engine behaviour Service call Result scope
    paragraph clear heading level — in place
    heading_1 set heading level 1 — in place
    heading_2 set heading level 2 — in place
    heading_3 set heading level 3 — in place
    code_block insert empty fenced code block — in place
    mermaid_diagram insert empty Mermaid fence — in place
    math_equation insert empty $$ block — in place
    quote prefix the block with > — in place
    table insert an empty GFM pipe table — in place
    ai_rewrite selection required ai_transform_block(rewrite) insert at caret
    ai_format_selection selection required ai_transform_block(format) insert at caret
    ai_summarize_selection selection required ai_transform_block(summarize) insert at caret
    ai_structure_journal journal pages only ai_transform_block(structure, page_path) replace page
    ai_format_journal_notes journal pages only ai_transform_block(format, page_path) replace page
    ai_structure_page non-journal pages ai_transform_block(structure, page_path) replace page
    ai_summarize_page non-journal pages ai_transform_block(summarize, page_path) replace page
    ai_research selection or page text ai_research replace page
    ai_interlink whole page ai_interlink_notes(page_path) replace page
    ai_generate_mermaid selection or page text generate_mermaid insert block after caret

    Divergence from the shipped BlockNote menu¶

    The shipped web editor builds its menu from getDefaultReactSlashMenuItems(editor) plus the AI items in src/components/AISlashMenu.tsx, so it also offers bulleted, numbered and check lists, tables, media and emoji. The native catalogue is a deliberate subset, because the block model has no separate block kinds for lists, media or emoji:

    Shipped BlockNote item Native mapping
    Paragraph, Heading 1-3, Code block dedicated actions
    Quote quote action — the block content becomes > … and render classifies it as BlockKind::Quote
    Check list task markers (TODO/DOING/…), applied through the marker menu or typed :marker; markers serialize as .marker: properties
    Bulleted list every block is already an outliner list item (serialized as -), so there is no separate action
    Numbered list authored as 1. content; render classifies it as an ordered BlockKind::ListItem
    Table table action inserts an empty GFM pipe table; render classifies the block as BlockKind::Table
    Image / video / audio / file attachment markdown (![[assets/…]]) managed by AttachmentPanel, not the slash menu
    Emoji not offered

    The native editor stores a table as plain GFM pipe-table Markdown in a block's content. pkm_block::Table is the plain value model; pkm_markdown::parse_table and pkm_markdown::serialize_table implement the strict parser and canonical serializer, and the table action inserts stratum_editor::menus::table_skeleton(). The canonical form is byte-stable across open → markdown → open. render classifies a table block as BlockKind::Table, mutes its pipes and delimiter row as syntax spans, and keeps those spans visible on the focused line (hiding them would merge adjacent cells). Inline emphasis inside a cell is not decorated yet.

    Every visible label is a translation key; editor.quote and editor.table are part of EDITOR_I18N_KEYS and present in all eight locale catalogs.

    Right-clicking a row places the caret and opens the per-block context menu (context_menu.rs) anchored at the pointer. Its entries, in order, are read aloud, copy, cut, toggle task marker, set reminder (one hour from now) and clear reminder; labels resolve through stratum_i18n keys gated by CONTEXT_MENU_ITEMS. Escape or a click outside the popup dismisses it. Selecting an entry closes the menu and takes the normal dirty/debounced-save path; the engine owns clipboard, marker and reminder mutations. Read-aloud goes through ShellData::speak → StratumService::tts_speak → base64 decode → rodio playback on a detached thread, and providers without audio support return Ok(()).

    Save lifecycle¶

    Edits mark the document dirty and schedule a debounced (400 ms) save with a generation counter so a burst of keystrokes produces one write. The save chip uses editor.saving and settings.saved; a failed write keeps the document dirty and surfaces the provider error. Saves go through the same blocks_to_dto seam as the service layer, so block fields stay identical.

    Attachments, drag-and-drop and paste upload¶

    Asset embeds (![[assets/foo.png]]) are classified by stratum_editor::assets::asset_kind: raster extensions (png, jpg, jpeg, gif, webp, bmp) are AssetKind::Image; everything else, including svg (the raster decoder does not handle it), is an AssetKind::File row. Only the embed form is an asset span — the plain [[assets/foo.png]] form stays a wiki link so it round-trips byte-identically.

    Row promotion is a whole-content gate, matching the shipped ^\s*!\[\[…\]\]\s*$ converter: only a block whose entire content is a single ![[…]] embed (surrounding whitespace allowed) becomes an attachment row. stratum_editor::assets::first_asset_span returns None for any mixed content (prefix/suffix text, another span kind such as a wiki link/tag/emphasis, or two embeds), so the row keeps the inline asset chip rendered through visible_runs/StyledText and the normal text height instead of losing its text. The view relies on this gate for both renders_as_asset and the virtual layout height reservation; there is no second mixed-content check in the UI.

    Rendering is split so the logic stays in the crates:

    • panels/editor/asset_rows.rs renders an image row with the decoded thumbnail inside THUMBNAIL_BOX plus a caption line (basename, MIME, format_size label), and a file row with IconName::FileText, basename and size. Without a decoded thumbnail the row keeps the shipped chip fallback (path text on the theme's primary/secondary pair).
    • panels/editor/asset_state.rs owns the thumbnail budget, the attachment list and the drop-target resolution; panels/editor/asset_actions.rs owns the import/delete/picker flows. Both run file reads and provider calls on the gpui background executor, so no upload blocks a frame. A failed thumbnail decode records the path in EditorView::failed_thumbnails so one corrupt image is skipped in favour of the next image row instead of starving every later thumbnail. A successful delete calls AssetThumbnailCache::invalidate and clears the failed marker before rebuilding rows, so a deleted image cannot keep a stale thumbnail.
    • panels/editor/attachments.rs renders the attachment panel under the editor page: translated title, count, summed size, collapse toggle, attach button and one row per attachment (name, MIME chip, size, delete). Delete is the shipped two-step inline confirmation — the first click arms the row and shows asset.delete_confirm, the second click deletes.

    Upload policy lives in stratum_app::asset (asset.rs plus asset/image.rs) and pkm_block::assets (assets.rs plus assets/store.rs): ASSET_MAX_BYTES is 8 MiB like src/lib/assetUpload.ts; oversized images are downscaled to IMAGE_COMPRESS_MAX_EDGE (2048) and re-encoded as JPEG at quality IMAGE_JPEG_QUALITY (85) only when the result is smaller, matching compressImage; an oversized non-image fails with the exact "file_too_large" sentinel the panel translates. Thumbnails decode through StratumService::asset_thumbnail at THUMBNAIL_MAX_EDGE (512) and are cached in the bounded AssetThumbnailCache (32 entries, LRU).

    Interaction:

    • Drag and drop. view.rs registers .on_drop::<ExternalPaths> on the editor root, resolves the row under window.mouse_position() through row_index_at_point (falling back to the caret block) and imports every dropped file through ShellData::import_asset_path (the service reads the file and applies the upload policy, so an 8 MiB drop never round-trips through base64 in the shell), then inserts the ![[…]] reference through EditorState::insert_asset_reference — one undoable history entry, dirty marking and the normal debounced save.
    • Paste. Ctrl+V with a ClipboardEntry::Image uploads the image with the MIME derived from the clipboard format (paste.png fallback name) instead of pasting text; a text clipboard keeps the previous normalize-and-insert path.
    • Attach button. attach_files opens the platform file picker (PathPromptOptions) and imports the selection through the same flow.

    The panel labels are release-gated in EDITOR_VIEW_I18N_KEYS (asset.attach, asset.attachments, asset.compressing, asset.delete, asset.delete_confirm, asset.empty, asset.file_too_large, asset.upload_failed); all eight catalogs already carry them, so no catalog edit was needed.

    Phase-B boundary¶

    The gpui view renders DecoratedRows and forwards input events to EditorState. It must not re-implement parsing, marker detection, undo, clipboard normalization or height estimation; those stay in the headless crate so they remain unit-tested and platform-independent. The dto module is the seam to stratum_app::block::BlockDto and must stay field-compatible.

    Phase B includes the per-block context menu, read-aloud through ShellData::speak and block drag-and-drop reordering (see Drag-and-drop reordering above). Reminder mutations go through EditorState::set_block_reminder, which routes the write through EditorDocument::mutate so revision and dirty bookkeeping stay in the document.

    Block drag-and-drop (moving a block between parents) is still out of phase B. Asset handling is in: thumbnails, the file-size row, external file drops, paste upload, the attachment list and inline delete all ship in the view described above; the React AttachmentPanel is no longer needed for attachment work in the native shell. The plain [[assets/foo.png]] form deliberately stays a wiki link so it round-trips byte-identically.

    10k Performance Capture¶

    src/bin/editor_perf.rs (binary stratum-editor-perf) opens the editor on the deterministic 10 000-block fixture in a 1280×720 window, sweeps the virtual list through the full content height for STRATUM_PERF_FRAMES frames (default 600), records frame deltas and the editor's row-materialization durations, writes JSON to STRATUM_PERF_OUT and quits.

    scripts/capture-gpui-editor-perf.sh starts Xvfb when DISPLAY is unset, builds the release binary, runs it, prints the numbers and exits non-zero only when render_p95_ms exceeds the 55 fps work budget (18.18 ms). Frame pacing under software rendering is reported but not gated. The gate deliberately measures the release build: a debug build spends an order of magnitude more time building row elements, so its numbers say nothing about the 55 fps target (STRATUM_PERF_PROFILE=debug reproduces a debug run). Math/Mermaid asset rendering is budgeted to one new asset per frame, cached afterwards and reported separately as asset_p95_ms; attachment thumbnail decodes share that budget and the same figure. It is excluded from the row-materialization figure because a single diagram render can legitimately exceed one frame's budget.

    Reference-run measurement (Xvfb, LIBGL_ALWAYS_SOFTWARE=1, release build, 600 frames, 10 000 blocks):

    Metric Value
    Blocks / rows 10 000 / 10 000
    Rows materialised per frame 2
    Row-build render_p95_ms 3.87 ms (budget 18.18 ms)
    Asset asset_p95_ms 0.004 ms
    Frame p50 / p95 / p99 / max 16.7 / 33.4 / 34.1 / 50.8 ms
    Derived frame fps p50 / p95 60.0 / 29.9

    The frame deltas are dominated by the software swapchain pacing under Xvfb, not by editor work; the gated measurement is the row-build p95, which is an order of magnitude below the budget. The JSON report is written to .hermes/perf/editor-10k-frames.json (gitignored).

    Translation Keys¶

    The crate never carries English UI strings. Models expose translation keys plus interpolation variables, and EDITOR_I18N_KEYS is the release gate list mirroring stratum_ui::SHELL_I18N_KEYS. tests/contract.rs verifies every key against crates/stratum-i18n/locales/en.json and checks that every slash-item key is a member.

    Building and Testing¶

    # Formatting
cargo fmt --all --check

# Clippy (warnings are errors)
cargo clippy -p stratum-editor --all-targets -- -D warnings

# Unit, integration and contract tests
cargo test -p stratum-editor

# View and window-free contract tests
cargo test -p stratum-ui

# Clippy for the view (warnings are errors)
cargo clippy -p stratum-editor -p stratum-ui --all-targets -- -D warnings

# 10k perf capture (Xvfb when DISPLAY is unset)
./scripts/capture-gpui-editor-perf.sh

    The attachment suite is window-free: pkm-block covers classification and the store round-trip, stratum-app covers thumbnail scaling, the 8 MiB upload boundary and the compression-parity rule, stratum-editor covers the reserved row heights, labels and the LRU thumbnail cache, and stratum-ui covers the fixture asset round-trip, the default trait methods and the translated upload-error mapping. Drop and paste gestures themselves need a window and are covered only by the fixture provider round-trip plus the pure drop-target and paste-payload helpers.

    The GPUI CI workflow includes crates/stratum-editor/** and scripts/capture-gpui-editor-perf.sh in its path filters, runs the crate and view build/test/clippy gates alongside stratum-i18n, and captures the 10k perf report in the screenshot job.
